1. Decision summary

This study compares two systems that expose the same System One decision interface: a caller provides state and a constrained question, and the model chooses an option or returns a yes/no probability. The comparison is intentionally about classification, routing, tool-call gating, guardrails, and judging. It is not a test of open-ended generation or multi-step planning.

Protocol controls

  • Prompts were frozen and pre-registered before the full run. Both models received the same decision payloads.
  • Accuracy, macro-F1, calibration, selective accuracy at confidence thresholds, AUROC, latency, cost, and exact paired McNemar comparisons were recorded.
  • Decider received warm-up requests. Errors after six retries were counted and excluded from accuracy. Ten When2Call inputs above 4,096 tokens were rejected cleanly by strict-window mode.
  • End-to-end latency is directional only because Decider was measured on localhost and Jev over the internet from India. Decider server time is the fair model-only comparison.
Interpretation boundary: this is one run per system. It supports workload-fit decisions, not universal model rankings. Jev training data is unknown. HaluEval is derived from HotpotQA, which is in the Decider training mix, and Decider was iterated against the public JevBench set.

5. Workload-specific findings

5.1 Tool-call gating is the main risk

On When2Call, Decider correctly identified tool calls 82.6% of the time and requests for missing information 78.4%, but recognised “cannot answer with the available tools” only 36.9% of the time. When no tools were offered, it was correct on 46.1% of items. It selected a tool when it should not have on 26.2% of items, compared with Jev at 8.9%.

Control recommendation: if Decider is used in an agent loop, add an explicit policy layer that validates tool eligibility, required arguments, tool availability, and an abstain/cannot-answer path. Do not treat the model's top option as authorization by itself.

5.2 Intent routing is the strongest Decider fit

Decider beat Jev on Banking77 and had lower ECE, 0.032 versus 0.091. On CLINC it trailed overall and was weaker at out-of-scope recall, 0.612 versus 0.852, although its out-of-scope precision was higher, 0.944 versus 0.873. This suggests a conservative router that can work well when the class inventory is stable and abstention is acceptable.

5.3 Binary outputs require calibration

At the default 0.5 threshold, Decider's positive F1 was 0.095 on injection and 0.432 on HaluEval. Its AUROC was materially better, 0.870 and 0.911, showing ranking signal rather than reliable default thresholding. The post-hoc best thresholds were fitted on the test set and are optimistic. A production implementation needs a held-out calibration set per question type.

6. Modalities and input limits

The two systems are not equivalent on input. This is a capability boundary that should drive architecture as much as the accuracy tables do. It was not benchmarked in this study; the figures below come from vendor and project documentation.

Unverified capability claims. The Decider project reports vision accuracy of 0.784 on NaturalBench, 0.877 on POPE-adversarial, and 37/60 on the Image-JevBench preview (one run, on an H100; not reproduced here). The same document notes that with the image removed the model still answers at a mean confidence of 0.65–0.73, so its image-conditioned confidence is not a strong grounding signal on its own. Treat these numbers as vendor-reported until independently reproduced.
Architecture implication: for screenshot or photo triage, Decider is the only one of the two that can take the image directly. For long policy documents, transcripts, or multi-document states, Jev's 64k window is the deciding factor. Where an image decision is needed and the model must be Jev, a separate vision-to-text step has to be designed, owned, and monitored.

At the measured prompt sizes, the estimated break-even is approximately 6–10 million Jev decisions per month. One Decider box can serve at most about 13 million per month sequentially, and that comparison assumes full utilisation. This makes self-hosting economically attractive only for steady, high-volume workloads and only after serving reliability is fixed.

Confidence is useful but conservative

On Banking77, Decider was 97.8% accurate at confidence ≥0.9, but coverage was 48.3%. On When2Call, it was 97.4% accurate at that threshold with only 4.2% coverage. Jev had much higher coverage but was below 95% accuracy at ≥0.9 on several tasks. Confidence should therefore drive selective routing, not unconditional trust.

For a Decider deployment, the minimum production shape is not a direct caller-to-GPU connection. It is a decision gateway that validates inputs, enforces the context window, serializes or safely schedules requests, checks the selected action against policy, and exposes health, error, confidence, and calibration telemetry.

9. Recommendation and next steps

Recommended now

  1. Use Jev for production agent gating, guardrails, groundedness judging, and general decision workloads.
  2. Evaluate Decider selectively for stable, high-volume intent routing where self-hosting, data locality, or predictable model-side latency is a requirement.
  3. Do not claim cost savings from self-hosting by default. The GPU only wins economically near sustained high utilisation.

Promotion gates for Decider

GateAcceptance criterion
ReliabilityParallel load, queue saturation, restart, and malformed/over-window inputs complete without sticky GPU failure.
QualityMeet workload-specific accuracy and false-action thresholds on a held-out representative set, not only public datasets.
CalibrationPer-task thresholds selected on validation data; confidence coverage and error rates monitored in production.
EconomicsForecasted utilisation exceeds the self-hosting break-even after capacity, storage, operations, and redundancy costs.
GovernanceVersioned model/checkpoint, dataset lineage, audit logs, access controls, and rollback procedure are documented.

Limitations

  • One run per backend. No retraining or seed variance estimate.
  • End-to-end latency paths are not equivalent.
  • HaluEval contamination and JevBench selection pressure limit generalisation claims.
  • Prompt-injection dataset is small and uses a broad definition that includes role-play prompts.
  • Vision capability and accuracy are vendor-reported and were not reproduced in this study; only text decisions were benchmarked.
  • Tic-tac-toe pilot showed neither model plans reliably; these are decision classifiers, not game planners.
